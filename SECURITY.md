# Security Policy

## Overview

CrediMerge is an AI-powered debt management and credit-health platform
designed to help users understand cash flow, manage multiple loans,
explore consolidation scenarios, and make informed financial decisions.

Because CrediMerge may process financial and authentication-related
information, security is a core part of the project.

> **Important:** CrediMerge provides estimates and educational guidance.
> It is not a credit bureau, lender, or substitute for professional
> financial advice. Scores generated by CrediMerge are not official
> CIBIL scores and do not guarantee loan approval.

## Supported Versions

Security fixes are primarily applied to the latest version of the
project.

  Version          Supported
  ---------------- -------------
  Latest / main    Yes
  Older versions   Best effort

## Security Principles

CrediMerge follows these principles:

-   Never commit API keys, passwords, tokens, or service-account
    credentials to Git.
-   Store secrets in environment variables.
-   Use HTTPS for deployed services.
-   Validate and sanitize user input.
-   Apply authentication and authorization before accessing private user
    data.
-   Restrict database access using appropriate Supabase/PostgreSQL
    policies.
-   Keep dependencies updated.
-   Avoid logging sensitive financial information.
-   Return only the minimum data required by an API response.

## Environment Variables

Secrets should be stored in `.env` files locally and in the
secret/environment-variable systems provided by the deployment platform.

Example:

``` env
GEMINI_API_KEY=your_key_here
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
FIREBASE_API_KEY=your_firebase_key
DATABASE_URL=your_database_url
```

Never commit real values.

Make sure `.env` files are included in `.gitignore`:

``` gitignore
.env
.env.local
.env.*.local
```

If a secret is accidentally committed, revoke or rotate it immediately.

## Authentication

CrediMerge uses Firebase Authentication for user authentication.

Recommended practices:

-   Require authentication for private user operations.
-   Verify Firebase ID tokens on protected backend endpoints.
-   Do not trust user IDs supplied directly by the client.
-   Use the authenticated user's identity when querying private records.
-   Never store plaintext passwords in the CrediMerge database.

## Database Security

CrediMerge uses Supabase/PostgreSQL for application data.

Recommended controls include:

-   Enable Row Level Security (RLS) for tables containing user-specific
    data.
-   Restrict INSERT, SELECT, UPDATE, and DELETE operations according to
    the authenticated user.
-   Never expose privileged database credentials to the frontend.
-   Keep service-role keys exclusively on trusted backend/server
    environments.
-   Use parameterized queries or safe database libraries to prevent SQL
    injection.

## API Security

Backend APIs should:

-   Validate request bodies and query parameters.
-   Authenticate protected requests.
-   Implement authorization checks.
-   Use rate limiting where appropriate.
-   Avoid exposing stack traces or internal implementation details in
    production.
-   Use secure CORS configuration.
-   Return safe error messages.

## AI and Financial Data

CrediMerge may use AI services such as Gemini for financial explanations
or assistance.

Do not send unnecessary sensitive information to external AI services.

Before sending data to an AI API:

1.  Collect only the required information.
2.  Remove unnecessary personally identifiable information.
3.  Validate the data.
4.  Use server-side API calls where possible.
5.  Never expose AI API keys in frontend source code.

AI-generated results should be treated as estimates and explanations
rather than guaranteed financial outcomes.

## Reporting a Vulnerability

If you discover a security vulnerability:

1.  Do not publish the vulnerability publicly.
2.  Do not include credentials, tokens, or private user data in a public
    issue.
3.  Contact the project maintainer privately.
4.  Provide a clear description, affected component, reproduction steps,
    and potential impact.

If a dedicated security contact is configured for the repository, use
that contact instead of opening a public issue.

## Security Checklist

Before deployment, verify:

-   [ ] No secrets are committed to Git.
-   [ ] `.env` files are ignored.
-   [ ] Production secrets are configured securely.
-   [ ] Firebase Authentication is enabled.
-   [ ] Supabase RLS policies are configured.
-   [ ] Service-role credentials are not exposed to the frontend.
-   [ ] API endpoints validate authentication and input.
-   [ ] CORS is configured for trusted origins.
-   [ ] HTTPS is enabled.
-   [ ] Production logs do not contain sensitive financial data.
-   [ ] Dependencies are reasonably up to date.

## Disclaimer

Security controls can reduce risk but cannot guarantee complete
security. CrediMerge should not be used to store or process sensitive
financial information beyond what is necessary for the application's
intended functionality.
